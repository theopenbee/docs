`openbee ctl` 是用于控制运行中的 openbee 服务器的命令行工具。所有子命令均通过已配置的 API 与本地服务器通信。

**全局参数**

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--config`、`-c` | string | `config.yaml` | 配置文件路径 |

---

## worker

管理 Worker 代理。

### worker list

列出所有已注册的 Worker，支持过滤和分页。

```bash
openbee ctl worker list [flags]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--department` | string | 否 | 按部门 ID 或名称过滤 |
| `--no-recursive` | bool | 否 | 仅返回直属于该部门的 Worker（不含子部门） |
| `--name` | string | 否 | 按名称过滤（大小写不敏感的部分匹配） |
| `--id` | string | 否 | 按 Worker ID 精确过滤 |
| `--page` | int | 否 | 页码（默认：1） |
| `--page-size` | int | 否 | 每页数量（默认：50，最大：200） |

### worker get

根据 ID 获取 Worker 详情。

```bash
openbee ctl worker get <id>
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | Worker UUID |

### worker status

获取 Worker 的当前状态。

```bash
openbee ctl worker status <id>
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | Worker UUID |

### worker create

创建一个新的 Worker。

```bash
openbee ctl worker create --name <name> [flags]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--name`、`-n` | string | 是 | Worker 名称 |
| `--description` | string | 否 | Worker 描述 |
| `--constraints` | string | 否 | Worker 约束内容 |
| `--work-dir` | string | 否 | 工作目录路径 |
| `--engine` | string | 否 | 使用的 AI 引擎（如 `claude`、`codex`、`pi`、`kimi`），留空表示使用服务器默认值 |
| `--department` | string | 否 | 部门 ID 或名称（多个部门用逗号分隔） |
| `--scopes` | string | 否 | 权限范围（逗号分隔，如 `read:workers,read:tasks`） |
| `--engine-args` | string | 否 | 各引擎的额外 CLI 参数，如 `"claude=--model claude-sonnet-4-6"`（可重复使用） |

### worker update

更新 Worker 属性（Patch 语义：未传入的字段保持不变）。

```bash
openbee ctl worker update <id> [flags]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | — | 是 | Worker UUID |
| `--name` | string | 否 | 新名称 |
| `--description` | string | 否 | 新描述 |
| `--constraints` | string | 否 | 新约束内容 |
| `--engine` | string | 否 | 使用的 AI 引擎（如 `claude`、`codex`、`pi`、`kimi`），留空表示保持不变 |
| `--department` | string | 否 | 部门 ID 或名称（逗号分隔），会替换所有关联。传入空字符串可清除关联 |
| `--scopes` | string | 否 | 权限范围（逗号分隔），会替换所有范围。传入空字符串可清除 |
| `--engine-args` | string | 否 | 各引擎的额外 CLI 参数（可重复使用），传入 `"claude="` 可清除 |

### worker delete

删除一个 Worker。

```bash
openbee ctl worker delete <id> [--delete-work-dir]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | — | 是 | Worker UUID |
| `--delete-work-dir` | bool | 否 | 同时从磁盘删除工作目录 |

## task

管理任务。

### task list

列出任务。`--session-key`、`--message-id`、`--worker-id` 至少需要提供一个。

```bash
openbee ctl task list [flags]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--session-key` | string | 条件必填 | 按 session key 过滤（与 `--message-id` 互斥） |
| `--message-id` | string | 条件必填 | 按消息 ID 过滤（与 `--session-key` 互斥） |
| `--worker-id` | string | 条件必填 | 按 Worker ID 过滤 |
| `--status` | string | 否 | 按状态过滤，支持逗号分隔（如 `pending,running`） |
| `--type` | string | 否 | 按类型过滤，支持逗号分隔（如 `immediate,countdown`） |

### task create

创建任务并直接指派给指定 Worker，绕过 Bee 的自动路由。

```bash
openbee ctl task create --message-id <id> --worker-id <id> --instruction <text> --type <type> [flags]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--message-id` | string | 是 | 来源平台消息的 ID |
| `--worker-id` | string | 是 | 目标 Worker UUID |
| `--instruction` | string | 是 | 给 Worker 的指令 |
| `--type` | string | 是 | 任务类型：`immediate`、`countdown` 或 `scheduled` |
| `--scheduled-at` | int64 | 条件必填 | Unix 毫秒时间戳；`countdown` 类型必填（需 ≥ 当前时间 + 5s） |
| `--cron` | string | 条件必填 | 5 字段 cron 表达式；`scheduled` 类型必填 |

**示例**

```bash
# 即时任务 — 数字员工可用时立即执行
openbee ctl task create \
  --message-id "msg-abc123" \
  --worker-id "worker-uuid" \
  --instruction "分析最新的部署日志并汇报所有错误" \
  --type immediate

# 倒计时任务 — 在指定时间执行（Unix 毫秒，需 ≥ 当前时间 + 5s）
openbee ctl task create \
  --message-id "msg-abc123" \
  --worker-id "worker-uuid" \
  --instruction "发送每日结束汇总报告" \
  --type countdown \
  --scheduled-at 1735660800000

# 定时任务 — 按 cron 计划周期性执行
openbee ctl task create \
  --message-id "msg-abc123" \
  --worker-id "worker-uuid" \
  --instruction "检查系统健康状态，如有服务异常则发出告警" \
  --type scheduled \
  --cron "0 * * * *"
```

如果 `--cron` 表达式无效，任务会以 `cancelled` 状态创建，并在 `reason` 字段中说明解析错误原因。

### task cancel

取消一个待执行或已调度的任务。

```bash
openbee ctl task cancel <id>
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | Task UUID |

## memory

管理持久化记忆条目。

### memory get

读取记忆条目。省略 `--key` 则返回指定 scope 下的所有条目。

```bash
openbee ctl memory get --scope <scope> [--key <key>]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--scope` | string | 是 | `global` 或某个 session key |
| `--key` | string | 否 | 记忆键；省略则返回该 scope 下所有条目 |

### memory save

保存或更新一条记忆。

```bash
openbee ctl memory save --scope <scope> --key <key> --value <value>
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--scope` | string | 是 | `global` 或某个 session key |
| `--key` | string | 是 | 记忆键 |
| `--value` | string | 是 | 记忆值 |

### memory delete

删除一条记忆。

```bash
openbee ctl memory delete --scope <scope> --key <key>
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--scope` | string | 是 | `global` 或某个 session key |
| `--key` | string | 是 | 记忆键 |

## session

管理会话上下文。

### session list

列出某 session key 下所有拥有活跃上下文的 Worker。

```bash
openbee ctl session list --session-key <key>
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--session-key` | string | 是 | 要查询的 session key |

### session clear

取消该 session 的所有活跃任务并清除所有会话上下文。

```bash
openbee ctl session clear --session-key <key> [--force]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--session-key` | string | 是 | 要清除的 session key |
| `--force` | bool | 否 | 当有多个 Worker 关联时跳过确认 |

### session clear-worker

重置某 session 中指定 Worker 的上下文。

```bash
openbee ctl session clear-worker --session-key <key> --worker-id <id>
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--session-key` | string | 是 | Session key |
| `--worker-id` | string | 是 | 要重置上下文的 Worker UUID |

## message

发送和查询平台消息。

### message send

向来源平台的用户发送消息。支持纯文本（通过 stdin）、媒体文件或二者同时发送。如需发送多个文件，请多次调用 `message send`，每次一个文件。

```bash
openbee ctl message send --message-id <id> [--stdin] [--media-path <path>]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--message-id` | string | 是 | 来源平台消息的 ID |
| `--stdin` | bool | 否 | 从 stdin 读取文本内容（配合 heredoc 使用） |
| `--media-path` | string | 否 | 要上传并发送的本地文件路径 |

`--stdin` 和 `--media-path` 至少需要提供一个。

**示例**

```bash
# 通过 heredoc 发送纯文本
openbee ctl message send --message-id <id> --stdin << 'EOF'
任务已完成。
EOF

# 发送文件
openbee ctl message send --message-id <id> --media-path /tmp/report.pdf

# 同时发送文本和文件
openbee ctl message send --message-id <id> --stdin --media-path /tmp/report.pdf << 'EOF'
报告见附件。
EOF
```

### message list

列出已接收的（入站）平台消息，支持过滤和分页。

```bash
openbee ctl message list [flags]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--session-key` | string | 否 | 按 session key 过滤 |
| `--platform` | string | 否 | 按平台过滤（如 `feishu`、`local`） |
| `--status` | string | 否 | 按状态过滤（`received`、`feeding`、`bee_processed`、`merged`、`failed`） |
| `--received-from` | int64 | 否 | 过滤 `received_at >=` 该值（Unix 毫秒） |
| `--received-to` | int64 | 否 | 过滤 `received_at <=` 该值（Unix 毫秒） |
| `--page` | int | 否 | 页码（默认：1） |
| `--page-size` | int | 否 | 每页数量（默认：50，最大：100） |

### message list-outbound

列出已发送的（出站）平台消息，支持过滤和分页。

```bash
openbee ctl message list-outbound [flags]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--session-key` | string | 否 | 按 session key 过滤 |
| `--platform` | string | 否 | 按平台过滤（如 `feishu`、`local`） |
| `--status` | string | 否 | 按状态过滤（`sent`、`failed`） |
| `--source-type` | string | 否 | 按来源类型过滤（`bee`、`worker`、`system`） |
| `--source-id` | string | 否 | 按来源 ID 过滤 |
| `--sent-from` | int64 | 否 | 过滤 `sent_at >=` 该值（Unix 毫秒） |
| `--sent-to` | int64 | 否 | 过滤 `sent_at <=` 该值（Unix 毫秒） |
| `--page` | int | 否 | 页码（默认：1） |
| `--page-size` | int | 否 | 每页数量（默认：50，最大：100） |
