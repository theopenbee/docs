---
title: /stop
description: 停止当前聊天中正在运行的 Bee，并取消队列中尚未处理的消息
---

立即停止当前聊天中正在运行的 Bee，并取消队列中尚未处理的待发消息。该指令只作用于你发送它所在的聊天会话，不影响其他会话。

## 语法

```text
/stop     # 停止当前会话中正在运行的 Bee，并取消待处理消息
```

`/stop` 不接受任何参数。

## 响应

系统根据执行指令时的实际状态返回不同的提示：

| 情况 | 提示信息 |
|------|----------|
| Bee 正在运行，无待处理消息 | `✅ 已停止 bee 执行` |
| Bee 正在运行，有待处理消息 | `✅ 已停止 bee 执行，取消了 N 条待处理消息` |
| Bee 未运行，有待处理消息 | `✅ 已取消 N 条待处理消息` |
| 无任何需要停止的内容 | `当前会话没有需要停止的内容` |

## 工作机制

发送 `/stop` 后，系统依次执行两步操作：

1. **取消 Bee 执行** — 若 Bee 正在运行，系统会立即取消其 Go context。取消信号会沿执行链路向下传播，Bee 在遇到下一个感知 context 取消的检查点时停止，不会等待当前轮次执行完毕。
2. **清理待处理消息** — 所有处于 `received`（已接收、待处理）状态的消息会被标记为 `failed`，防止 Bee 在停止后自动继续处理这些消息。

`/stop` **不会**清除会话上下文、停止 Worker 执行，也不会取消计划任务。如需这些操作，请使用 [`/clear`](./clear)。

## 什么时候用 `/stop`

- **中断耗时过长的回复**：Bee 响应太慢或答非所问 — 发一条 `/stop` 立即打断。
- **撤回刚发出的消息**：消息发出后还没被 Bee 处理，改变主意了 — `/stop` 可以从队列中清除它。
- **解除卡住的 Bee**：Bee 看起来没有反应、停滞不动 — `/stop` 强制终止执行。
- **执行完整重置前的准备**：先用 `/stop` 排空进行中的任务，再用 `/clear` 清除上下文，两步组合实现彻底重置。

## 注意事项

- **幂等性** — 在没有任何运行内容时调用 `/stop` 是安全的，会返回"当前会话没有需要停止的内容"，不产生任何副作用。
- **会话作用域** — 只影响你发送 `/stop` 所在的聊天，其他会话不受影响。
- **消息记录保留** — 被停止的消息在数据库中被标记为 `failed`，不会被删除。
- **无需二次确认** — 与有运行任务时的 `/clear` 不同，`/stop` 立即执行，不需要确认步骤。
