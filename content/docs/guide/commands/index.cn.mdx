---
title: 聊天指令
description: 在 IM 聊天中通过斜杠指令快速、确定地触发操作
---

除了使用自然语言（例如"清除会话"）之外，OpenBee 还支持一组可以直接在 IM 聊天中输入的斜杠指令。斜杠指令由系统直接解析，不经过 AI 引擎，所以**即刻执行、不消耗 token，行为完全确定**。

当你想要快速、可预期的结果时，用斜杠指令；自然语言的方式依然可用，但它要经过 Bee 的理解和判断。

## 概览

| 指令 | 作用 |
|------|------|
| [/engine](./engine) | 切换 Bee 或指定数字员工所用的 AI 引擎 |
| [/clear](./clear) | 清除当前聊天的会话上下文，可选只清理某一个数字员工 |
| [/stop](./stop) | 停止当前聊天中正在运行的 Bee，并取消队列中尚未处理的消息 |
| [/status](./status) | 显示当前会话中活跃的 Bee 及正在运行的任务 |
| [/list](./list) | 列出所有数字员工，可通过关键词过滤 |

所有指令在所有支持的 IM 平台（飞书、钉钉、企业微信、Telegram、微信以及本地聊天）上都能使用。它们必须是消息的**第一个词**——像"帮我执行 `/clear`"这样的表达会被当作普通消息发给 Bee，不会触发指令。

## 斜杠指令 vs. 自然对话

你也可以用普通聊天消息来表达同样的意图（例如"清除会话"、"把引擎切到 codex"）。两种方式都能用，但取舍不一样：

| | 斜杠指令 | 自然对话 |
|---|----------|----------|
| **速度** | 立即执行，不调用 AI | 较慢，需要 Bee 解读 |
| **成本** | 免费，不消耗 token | 消耗 Bee 的 token |
| **确定性** | 输入确定 → 结果确定 | 取决于 Bee 的理解 |
| **表达力** | 语法固定 | 可接受近似说法、同义词、多步意图 |
| **撤销** | 无撤销；只有破坏性 `/clear` 有确认 | Bee 对歧义的说法会主动追问 |

当你**非常明确**想做什么并且希望立刻生效时，用斜杠指令；当意图比较开放（比如"重置刚才那个一直报错的数字员工"）时，用自然对话更合适。

## 最佳实践

### 把 `/clear` 当成日常维护指令

把 `/clear` 当成"刷缓存"一样使用 — 切换话题、开始重要新任务之前，或者发现代理行为跑偏时都可以用。员工级 `/clear` 便宜且不破坏性，不用等整个会话坏掉才想起它。

### 用 `/engine` 前先确认引擎可用

只有服务端配置里启用的引擎才能被选中。如果 `/engine {name}` 返回 `未知的 engine`，说明这个引擎还没装或没配置 — 去 `config.yaml` 里修好，不要反复重试指令。

### 别在高峰时段跑 `/engine`

繁忙状态检查会拒绝切换，但反复尝试只会刷屏。最好在空闲时段统一切换引擎，或者先暂停消息再切。

### 优先用员工级 `/clear`，少用整体 `/clear`

整体 `/clear` 会取消正在运行的任务并抹掉 Bee 的协调历史。除非这正是你想要的，否则优先 `/clear {workerName}` — 精准清理，保留会话其他部分的状态。

### 用 `/stop` + `/clear` 实现彻底重置

`/stop` 负责排空进行中的任务，`/clear` 负责清除上下文。需要彻底重置时 — 没有运行中的 Bee、没有待处理消息、没有历史上下文 — 按顺序执行：先 `/stop`，看到确认后再 `/clear`。

### 执行破坏性操作前先用 `/status` 确认

在执行 `/stop` 或 `/clear` 之前，先跑一下 `/status` 看看当前有哪些任务在进行。它不消耗 token，却能给你一张清晰的快照，避免误中断你还关心的任务。

### 用 `/list` 按描述找数字员工

记不住员工准确名字时，用 `/list {关键词}` 按描述搜索。比翻管理后台快，而且直接在任何有 Bee 的聊天窗口里就能用。
