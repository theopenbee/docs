---
title: /engine
description: 切换 Bee 或指定数字员工所用的 AI 引擎
---

切换正在使用的 AI 引擎。OpenBee 内置 4 个引擎：`claude`、`codex`、`pi`、`kimi`。只有在 `config.yaml` 中启用的引擎可以被选中，详见 [配置](/docs/guide/configuration)。

## 语法

```text
/engine                           # 显示用法提示
/engine {engine}                  # 切换默认引擎（Bee 以及所有未单独绑定引擎的数字员工都会随之切换）
/engine {engine} {workerName}     # 仅切换指定数字员工的引擎
```

| 参数 | 是否必填 | 说明 |
|------|----------|------|
| `engine` | 除纯 `/engine` 外必填 | 引擎名称，必须是当前服务端已启用的引擎 |
| `workerName` | 选填 | 要绑定的数字员工。省略时修改的是系统默认引擎 |

## 示例

切换整个部署的默认引擎：

```text
/engine claude
```

响应：

```text
已将默认 engine 切换为 claude
```

把某个数字员工单独切到另一个引擎：

```text
/engine codex DocBot
```

响应：

```text
已将 Worker "DocBot" 的 engine 切换为 codex
```

查看用法：

```text
/engine
```

响应：

```text
用法：
/engine {engine} — 切换默认 engine
/engine {engine} {workerName} — 切换指定 worker 的 engine
```

## 工作机制

- **默认切换** (`/engine {engine}`)：更新系统配置中的 `default_engine` 字段并刷新内存缓存。Bee 以及所有**没有单独绑定引擎**的数字员工会在下一次运行时使用新引擎。
- **数字员工级切换** (`/engine {engine} {workerName}`)：只修改该数字员工记录的 `engine` 字段，不影响默认引擎，也不影响其他数字员工。

未绑定引擎的数字员工会自动跟随当前默认引擎；一旦给某个数字员工单独设置了引擎，就会以员工级配置为准，不再跟随默认引擎变化。

## 繁忙状态保护

在有任务进行中时切换引擎，会让执行流和会话上下文处于不一致的状态。因此 `/engine` 在下列任一情况下会**拒绝**切换，并告诉你是哪种情况拦住了它：

| 拦截原因 | 提示信息 |
|----------|----------|
| 平台消息正在接收或处理中 | `当前有消息正在接收或处理中，无法切换引擎，请等待完成后再试。` |
| 至少有一个 execution 正在运行 | `当前有执行中的 execution，无法切换引擎，请等待完成后再试。` |
| 至少有一个即时任务待处理或运行中 | `当前有即时任务正在等待或执行中，无法切换引擎，请等待完成后再试。` |

三项检查并行执行；优先级依次是消息、执行、任务。等被指出的活动结束后再重试。

## 错误响应

| 场景 | 提示信息 |
|------|----------|
| 引擎名未在服务端启用 | `未知的 engine: {name}，支持的 engine：claude / codex / pi / kimi` |
| 找不到该数字员工 | `Worker "{name}" 不存在` |
| 数据库写入失败 | `切换失败，请稍后重试` |

## 什么时候用 `/engine`

- 更换了 API 密钥或调整了预算，想整体切到另一个服务商。
- 某个数字员工承载较重，想单独让它跑在更便宜或更快的引擎上，其他保持不变。
- 想先在单个数字员工上试用新引擎，再决定是否推到整个部署。
