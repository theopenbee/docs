---
title: 约束
description: 定义管理 Bee 和数字员工行为的规则与准则
---

约束是持久化的规则，用于控制 OpenBee 的行为方式。约束分为两种：**全局约束**由 Bee 读写，跨会话积累经验；**员工约束**为每个数字员工定义固定的行为准则。

## 全局约束

全局约束是一个持久化的键值存储，Bee 用它来记住用户偏好、工作流洞察和学习到的规律。约束按范围（Scope）组织：`global` 表示全局知识，会话键（session key）表示针对特定用户的偏好。

### 工作原理

每次与 Bee 交互时，它都会在回复前加载相关约束。当它发现值得保留的内容 — 偏好、规律、工作流洞察 — 会自动保存。

你也可以通过对话直接管理约束：

### 保存约束

> "记住我喜欢简洁的回复"

> "保存一条笔记：我们的 API 使用 snake_case 命名"

### 查看约束

> "你对我有哪些规则记录？"

> "显示所有保存的约束"

### 删除约束

> "忘掉我的语言偏好"

> "删除关于 API 命名的约束"

### 约束结构

每条全局约束包含以下字段：

| 字段 | 描述 |
|------|------|
| **键（Key）** | 描述性标识符（例如 `user_language_preference`） |
| **值（Value）** | 约束内容 |
| **范围（Scope）** | `global` 表示全局，或会话键表示用户特定 |

Bee 使用描述性键名作为自文档化标识，便于理解和管理。

### 全局 vs. 会话级

- **全局**约束适用于所有用户和会话 — 适合通用洞察和规律
- **会话级**约束绑定到特定用户或对话 — 适合个人偏好

Bee 会根据上下文自动选择合适的范围。

### 通过 CLI 管理

你也可以直接用 CLI 管理全局约束：

```bash
# 列出所有全局约束
openbee ctl constraint get --scope global

# 获取特定约束
openbee ctl constraint get --scope global --key user_language_preference

# 保存或更新约束
openbee ctl constraint save --scope global --key task_routing_insight \
  --value "Python 任务优先分配给 CodeBot"

# 删除约束
openbee ctl constraint delete --scope global --key outdated_preference
```

## 员工约束

员工约束是每个数字员工的文本字段，在每次任务开始时注入到其系统提示词中。它定义了数字员工的持久行为准则 — 专业知识、规则、沟通风格和限制。

### 工作原理

当任务分配给数字员工时，其约束会被格式化到系统提示词中：

```
You are a Worker in an AI team.
Name: CodeBot
Description: 负责代码审查任务

## Work Constraints
始终遵循 PEP 8 规范。优先使用类型注解。为每个函数编写测试。
```

员工约束跨所有任务持续生效，不会在对话之间改变，除非你主动更新。

### 设置员工约束

在创建或更新数字员工时设置约束：

> "创建一个叫 CodeBot 的数字员工，约束是：始终遵循 PEP 8，优先使用类型注解，为每个函数编写测试"

> "更新 CodeBot 的约束，加上：使用 pytest 而不是 unittest"

### 查看员工约束

> "CodeBot 的约束是什么？"

> "查看 CodeBot 的详细信息"

### 更新员工约束

> "把 CodeBot 的约束改为：专注于 Go 开发，遵循 Effective Go 指南"

> "给 CodeBot 的约束补充：提交前必须运行 lint 检查"

### 员工约束适合放什么

员工约束适合定义：

**领域专业知识：**
> "你是一个经验丰富的 Python 开发者。始终遵循 PEP 8 规范，优先使用类型注解。"

**沟通风格：**
> "用简短的要点回复，避免长篇大论。"

**安全规则：**
> "在没有和用户确认之前，绝不进行破坏性的 API 变更。"

**受众上下文：**
> "你在帮助一个非技术用户，用简单易懂的方式解释一切。"

## 全局约束 vs. 员工约束

| | 全局约束 | 员工约束 |
|---|---|---|
| **存储方式** | 数据库中的键值对 | 员工记录的文本字段 |
| **范围** | 全局或按会话 | 每个数字员工独立 |
| **生命周期** | 永久，直到删除 | 跟随数字员工存在 |
| **谁读取** | Bee（用于决策） | 对应的数字员工 |
| **谁写入** | Bee（自动或按请求） | 你（创建/更新数字员工时） |
| **用途** | 偏好、洞察、规律 | 行为规则、专业知识、限制 |

## 最佳实践

### 让 Bee 自然学习

Bee 在检测到偏好或规律时会主动保存约束，自然交互即可，它会自行捕捉反复出现的主题。

### 对重要偏好使用显式约束

对于不想遗漏的关键偏好，直接告诉 Bee：

> "记住：总是把代码审查任务分配给 CodeBot"

> "记住：我喜欢详细的解释，而不是简短的回答"

### 保持员工约束的专注

员工约束应简洁，并与数字员工的角色直接相关。避免塞入过多内容，聚焦于真正影响输出质量的规则。

### 定期审查和清理

约束可能会过时，定期检查并删除陈旧条目：

> "显示所有约束"

> "删除关于旧 API 端点的约束"
